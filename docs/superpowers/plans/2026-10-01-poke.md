# Personal Poke Command Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add safe sequential `poke`/`tickle` requests for all saved ChatGPT accounts while retaining the existing daemon-restart customization in version-controlled source.

**Architecture:** Extend the npm Node launcher, not the Zig command parser. A focused Node module uses the existing native `export`/`import` commands and launches isolated, bounded Codex executions; Node integration tests supply fake native and Codex executables. Leave upstream commands and their JSON contract unchanged.

**Tech Stack:** Node ES modules, built-in `node:test`, `node:assert/strict`, filesystem and child-process APIs; existing native codex-auth 0.3.0 and installed Codex CLI 0.159.1.

**Spec:** `docs/superpowers/specs/2026-10-01-poke.md`

## Global Constraints

- Model default: `gpt-6-luna`; effort: `low`; user message: exact `ping!`.
- Sequential requests only; skip API-key accounts; no silent model fallback.
- Timeout default 120 seconds; accepted integers 1 through 3600.
- Never switch the real active auth, restart the daemon for a poke, or copy user configuration into temporary homes.
- Private credential directories `0700`, files `0600`; clean up on handled exits and cancellation.
- Preserve refreshed credentials only for the same identity; refuse to overwrite a changed source snapshot.
- No new runtime libraries, no changes to `.zig`, and English CLI output only.
- Do not make live model requests, publish commits, create a GitHub fork, or change git remotes during implementation without further authorization.
- Keep low-level details in `docs/`, not README.

## Review Focus

- One account has expired auth, lacks the model, or is rate-limited: fail that account without fallback and still visit later accounts.
- Ambient API credentials or an API-key account: never accidentally bill an API key or use it instead of the saved ChatGPT login.
- Corrupt snapshots or failed export: avoid sending with the wrong login and do not leak raw child output.
- Hung execution, cancellation, or a second simultaneous poke: terminate children, clean credentials, and reject overlapping personal runs.
- Token refresh or concurrent source edits: validate identity, persist eligible refreshes, refuse stale overwrites, and leave the real active auth unchanged.

### Task 2: Implement and Test Isolated Pokes

// parsePokeArgs(argv: string[]) -> { model: string, timeoutSeconds: number,

//   -> { args: string[], env: object, cwd: string }
// runPoke(options: { binaryPath: string, argv: string[], env?: object,

- [ ] **Step 1: Write initial unit tests.**

```js
import test from 'node:test';
import assert from 'node:assert/strict';
import { parsePokeArgs, buildPokeInvocation } from '../bin/personal-poke.mjs';

test('defaults match the requested inexpensive ping', () => {
  assert.deepEqual(parsePokeArgs([]), {
    model: 'gpt-6-luna', timeoutSeconds: 120, dryRun: false, help: false,
  });
});

test('reject invalid or unsupported options before touching accounts', () => {
  for (const argv of [
    ['--timeout', '0'], ['--timeout', '-1'], ['--timeout', '1.5'],
    ['--timeout', '3601'], ['--timeout'], ['--model'], ['--unknown'],
    ['unexpected-account-selector'],
  ]) assert.throws(() => parsePokeArgs(argv));
});

test('request is isolated from ambient API keys and user config', () => {
  const invocation = buildPokeInvocation('/tmp/private-fixture', 'gpt-6-luna', {
    PATH: '/fixture/bin', OPENAI_API_KEY: 'fake-key',
    CODEX_API_KEY: 'fake-key', OPENAI_BASE_URL: 'https://invalid.example',
  });
  assert.equal(invocation.env.CODEX_HOME, '/tmp/private-fixture');
  assert.equal(invocation.env.OPENAI_API_KEY, undefined);
  assert.equal(invocation.env.CODEX_API_KEY, undefined);
  assert.equal(invocation.env.OPENAI_BASE_URL, undefined);
  assert.equal(invocation.args.at(-1), 'ping!');
  assert.ok(invocation.args.includes('model_reasoning_effort="low"'));
  assert.ok(invocation.args.includes('--ignore-user-config'));
  assert.ok(invocation.args.includes('--ephemeral'));
  assert.ok(invocation.args.includes('read-only'));
});
```

Run `node --test tests/personal_poke_test.mjs`. Expected: module-not-found failure.

- [ ] **Step 4: Implement the orchestrator with native export/import.** Resolve original home from `CODEX_HOME` or the OS home before constructing child environments. Read each independently, reject corrupt or incomplete ChatGPT auth, skip API-key auth, and identify accounts from the JWT user claim and `tokens.account_id` using the same precedence as `src/auth/auth.zig`. Display an email/account identifier, not tokens. Create one fresh private Codex home per eligible account; write only that account's `auth.json` with mode `0600`. Report exit success as request success, not confirmation of a new five-hour window.

Keep an original-byte snapshot of each exported credential. After the child finishes, examine its auth file even if the request failed: retain valid same-identity refreshes. Compare the corresponding original source snapshot against the exported baseline before import; on conflict, do not import, report a conflict, and return a failure status. Place eligible refresh files into a dedicated private directory and invoke native `import <directory>` while the original `CODEX_HOME` remains selected. Directory import avoids the single-file account-name refresh path. Do not touch the source active auth. Document that this check is not an atomic compare-and-swap against unrelated native writers.

Use asynchronous `spawn`, a per-child timeout, and SIGINT/SIGTERM handlers. On timeout/cancellation, terminate the child's process group on Unix (normal child termination elsewhere), escalate after a short grace period, await exit, and clean in `finally`.
