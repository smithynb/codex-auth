# Personal poke/tickle command

## Requested behavior

Add `codex-auth poke` and the synonymous `codex-auth tickle`. Visit every stored ChatGPT account sequentially, authenticate using its saved credentials, and send the exact user message `ping!` using `gpt-6-luna` with `model_reasoning_effort="low"`.

The purpose is to initiate an account's five-hour usage window with a small request. A successful request is not proof that a new window started: existing windows, plan-specific limits, model access, and reset timing remain controlled by OpenAI. Do not claim this is a free request, resets an existing limit, or bypasses a limit. The model name is the user's selection, not an independently verified cheapest-model claim. The local model cache lists `gpt-6-luna` and supports `low`.

## Safety and scope

- Preserve the user's active authentication file, active account selection, account aliases, and running daemon. Do not implement this by switching the real active account repeatedly.
- Use isolated private temporary Codex homes and empty working directories. Send a developer instruction requesting only a minimal acknowledgement and forbidding tools, file access, shell commands, and other actions. Use read-only sandboxing, ephemeral sessions, and no user configuration. The message itself remains exactly `ping!`.
- Skip API-key accounts: their usage is not a ChatGPT subscription five-hour window and could incur API billing.
- Never silently substitute a different model or reasoning effort. Continue to the next account after an individual failure. Report truthful per-account success/failure/skipped statuses and totals; partial failure returns exit code 1.
- Add `--dry-run`, `--model <name>`, and `--timeout <seconds>` (default 120, positive integers up to 3600), plus help. Dry-run must not invoke Codex, refresh authentication, or send requests.
- Bound child execution and handle cancellation. Remove temporary credentials on normal completion, failure, timeout, SIGINT, and SIGTERM. SIGKILL and power loss cannot guarantee cleanup; document this limitation.
- Do not print auth JSON, JWTs, access tokens, refresh tokens, API keys, or unfiltered child diagnostics. Treat child output as potentially sensitive.
- If Codex refreshes credentials, retain same-identity refreshed auth through native import without replacing the real active auth file. Detect a changed source snapshot before import and refuse to overwrite newer credentials. Serialize poke/tickle runs; do not claim concurrency safety against unrelated upstream writers that do not share the personal lock.
- Transfer the installed launcher's existing interactive daemon-restart prompt into the checkout unchanged in behavior: successful interactive switch, changed auth fingerprint, default yes; never prompt for JSON/help/failed/unchanged/non-TTY operations.
- Keep personal features in the Node launcher and a focused Node module, avoiding modifications to the Zig core or new runtime libraries. All CLI text is English.
- Test with fake credentials, fake Codex, and fake native binaries. Do not run a real multi-account poke during development without a separate request.
